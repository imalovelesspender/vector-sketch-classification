# 345-class LSTM directionality ablation (independent, prepared, not yet run)

Question: on all 345 QuickDraw classes, does reading the stroke sequence in both
directions help, and is any gain explained by the larger final embedding?

This is an independent controlled ablation run from Mae's PSC project directory
(`/ocean/projects/cis260329p/mcui3/`). It does not use Anson's private run
directory. All three runs, including the bidirectional reference, are trained
fresh on the same regenerated data and the same fixed sample IDs. Anson's archived
BiLSTM-256 result (75.19% valid) is context only, not one arm of this comparison.

| Task | Run | `bidirectional` | `hidden_dim` | Embedding | Parameters | Output |
|---|---|---|---|---|---|---|
| 0 | BiLSTM-256x2 (reference) | true | 256 | 512 | 711,513 | `results/lstm345_dir_bi256` |
| 1 | UniLSTM-512 | false | 512 | 512 | 1,235,801 | `results/lstm345_dir_uni512` |
| 2 | UniLSTM-256 | false | 256 | 256 | 355,929 | `results/lstm345_dir_uni256` |

Comparisons: 0 vs 1 (same embedding size), 0 vs 2 (same per-direction hidden size;
task 2 is one direction of task 0's encoder).

## What is held identical

- Code: Mae's pipeline at `5fe0e29` plus Anson's archived adapter `run_processed.py`.
  Every `src/` file and the adapter are SHA-256 checked (`historical_source_hashes.json`).
- Data: `data/processed_full` regenerated by Sihui's `data_preprocessing/preprocess.ipynb`
  (branch `data-preprocessing` @ `a2153dd`, notebook SHA-256 `af55d144…`, the version
  Anson's README records). The only change is `DOWNLOAD_BOTH_VERSIONS=False`, so only
  the 345 `.full.npz` archives (6.45 GiB) are downloaded. The standard archives
  are not used. `run_notebook.py` executes the notebook's code cells unchanged otherwise.
- Classes: all 345, manifest `class_to_index` order. This order is checked against the
  archived config's category list and label mapping.
- Samples: >250-point sketches excluded; 5,000 train / 500 valid per class;
  `default_rng(42)` per split. The IDs are fixed once by `make_selection.py`, and every run
  asserts that its loaded IDs equal those lists exactly.
- Settings: the resolved config must equal the archived BiLSTM-256 `config.json`
  (`reference_bi256_config.json`, SHA-256 `b62e0699…`). Allowed differences are only data
  location, manifest path/hash and adapter path. Seed 42, batch 128, Adam 1e-3,
  weight decay 0, grad clip 1.0, 10 epochs, last pooling, dropout 0,
  best-on-validation checkpoint. The test split is not touched.
- Only `model.bidirectional`, `model.hidden_dim` and `output_dir` differ between tasks.
- Hardware/software: GPU-shared, 1x V100-32, 5 CPUs, `pytorch/26.05-2.11-py3`.

## Files (`psc_run/`)

- `run_notebook.py`: headless execution of the preprocessing notebook.
- `verify_processed.py`: checks manifest metadata, all 1,035 shards and the normalization
  (processed train coordinates have std 1). It also re-derives a few categories from the raw archives.
- `make_selection.py`: writes `selection/{train,valid}_sample_ids.json`.
- `run_direction345.py`: training runner, modeled on Anson's `run_hidden345.py`.
- `preflight_direction345.py`: read-only checks before any GPU request.
- `prepare_data.sbatch`, `direction345.sbatch`: SLURM scripts.
- `run_processed.py`, `historical_source_hashes.json`, `reference_bi256_config.json`,
  `anson_{train,valid}_class_counts.json`: copied unchanged from
  `docs/experiments/lstm_345class_20261014/`.

## Steps on PSC

```bash
M=/ocean/projects/cis260329p/mcui3
git clone https://github.com/imalovelesspender/vector-sketch-classification.git $M/qd-data && git -C $M/qd-data checkout a2153dd
git clone https://github.com/imalovelesspender/vector-sketch-classification.git $M/qd-ablation && git -C $M/qd-ablation checkout 5fe0e29
# copy this folder's psc_run/ into $M/qd-ablation/psc_run/
cd $M/qd-data && module load pytorch/26.05-2.11-py3
SSL_CERT_FILE=/etc/pki/tls/certs/ca-bundle.crt python ../qd-ablation/psc_run/run_notebook.py --stop-after-download  # login node
cd $M/qd-ablation
sbatch --export=ALL,DATA_REPO=$M/qd-data psc_run/prepare_data.sbatch     # preprocess + verify + selection
python psc_run/preflight_direction345.py --data-dir $M/qd-data/data/processed_full --selection-dir selection
sbatch --export=ALL,DATA_DIR=$M/qd-data/data/processed_full psc_run/direction345.sbatch
```

(The module's Python has no CA bundle of its own, so the download needs `SSL_CERT_FILE`.)

## Caveats

- Single seed, fixed 10-epoch budget. cuDNN is not deterministic, so reruns can differ slightly.
- UniLSTM-512 has more parameters than BiLSTM-256x2 (1.24M vs 0.71M).
- Compare on validation only. Test evaluation is a separate decision.
- Regenerated data may differ in manifest bytes from Anson's (`f5810fec…`), because the
  notebook records per-category statistics in thread-completion order. That is why
  this ablation uses its own BiLSTM reference.
